# 작업 지시 이해 지원 서비스 로컬 시연 설계

## 시연 목표

관리자가 변경 공지를 발행해 카카오톡 단체방에 링크를 공유한다. 5분 발표에서는 한 노트북의 화면을 공유하고 PC 카카오톡 메시지에서 작업자 링크를 연다. 작업자가 영어로 행동을 설명하면 AI가 첫 답에서 빠진 조건을 한 번 되묻고, 두 답을 종합해 이해를 확인하는 장면까지 보여준다.

## 구성과 선택 이유

Next.js App Router 한 앱에서 화면과 서버 API를 제공하고 SQLite 파일에 작성 중인 공지와 발행본을 보관한다. 새 공지 작성(`/`), 작성 중 원문 수정(`/admin/edit/[id]`), 퀴즈 검수(`/admin/quiz/[id]`), 작업자 화면 미리보기(`/admin/preview/[id]`), 발행된 작업자 화면(`/n/[id]`)을 별도 경로로 구성한다. 퀴즈·미리보기 경로는 서버에서 저장된 작성 상태를 읽어 새로고침해도 유지된다. 원문을 수정하면 기존 미리보기를 무효화하고 퀴즈를 다시 생성한다. 이번에는 발표 노트북에서 실행한다. 공지 링크는 해당 노트북의 새 탭에서 연다.

## 관리자 흐름

로컬 MVP에서는 관리자가 로그인 없이 관리자 화면을 열고 초안 생성부터 발행까지 진행한다.

1. 한국어 원문을 입력한다. AI가 변경 행동, 적용 시점과 조건, 적용형 상황 질문 한 개, 답에서 확인할 행동과 원문 근거를 생성한다. 퀴즈 기준은 [이해 확인 퀴즈 기준](../../quiz-policy.md)을 따른다.
2. 관리자가 퀴즈 페이지에서 질문, 판단 기준, 원문 근거를 검수·수정하고 영어 미리보기를 생성한다. 미리보기 페이지에서 작업자에게 보이는 공지와 질문을 확인하고 표현을 수정할 수 있다. 같은 작성 ID의 이전 버전으로는 발행할 수 없다.
3. 발행 시 미리보기의 영어 공지와 질문, 검수한 기준, 원문을 함께 저장한다. 발행 과정에는 AI 호출이 없다. 발행 후에도 관리자 미리보기 페이지는 남고 확정된 문구를 읽기 전용으로 표시한다. 관리자는 공지 링크를 복사해 카카오톡 단체방에 붙여넣는다. 로컬 시연에서는 같은 노트북의 PC 카카오톡에서 링크를 연다. 작업자에게 보내는 데이터에는 내부 판단 기준을 포함하지 않는다.

## 작업자 흐름

관리자 화면의 마지막 동작은 `[발행] → [공지 링크 복사]`이다. 복사 성공 후 단체방에 붙여넣으라고 안내하고, 메시지 전송은 관리자가 직접 한다. 작업자가 메시지의 링크를 누르면 로그인 없이 발행된 영어 공지와 상황 질문이 열린다. 작업자 페이지 열람과 카카오톡 링크 미리보기는 저장된 데이터를 읽기만 한다. 작업자 흐름에서 AI를 호출하는 시점은 답변이나 질문을 제출할 때다.

영어 공지와 상황 질문을 읽고 같은 입력창에 행동이나 질문을 영어로 입력한다. 서버는 발행본에 근거해 응답을 판단한다. 응답 세션은 작업자별로 구분하고 후속 답을 판단할 때 첫 답과 실제 되물은 질문도 함께 전달한다.

| 입력 상황 | 동작 |
| --- | --- |
| 기준을 충족하는 행동 | 이해 확인 후 종료 |
| 원문 지시에 어긋나는 행동 | 근거에 해당하는 행동을 영어로 안내하고 종료 |
| 행동이 모호한 첫 답 | 빠진 행동만 한 번 되묻기 |
| 되물은 뒤의 답 | 앞뒤 답을 함께 판단. 여전히 모호하면 공지에 나온 행동을 영어로 안내하고 종료 |
| 작업자가 직접 질문 | 공지로 답할 수 있으면 근거에 따라 영어로 답변. 행동 이해를 확인한 것으로 기록하지 않음 |
| 공지 근거가 부족함 | 관리자 확인 필요 표시 |

되묻기 횟수는 서버가 제한한다. AI 호출 실패는 이해 확인으로 처리하지 않으며, 입력을 보존해 재시도할 수 있게 한다. 관리자에게 실제 요청을 전달하거나 답변을 등록하는 기능, 게시판, QR은 이번 범위에서 제외한다.

## 리허설 확인 항목

- 로컬에서는 관리자 화면에서 복사한 링크를 PC 카카오톡에 붙여넣고, 서버가 실행 중인 같은 노트북에서 열어 검수한 영어 공지와 퀴즈가 보이는지 확인한다.

- 오후 2시 옥상 작업 중단과 공구를 두고 내려오라는 공지를 사용한다. 관리자가 수정한 질문이 미리보기와 발행본에서 일치해야 한다.
- 첫 답 “I’ll go downstairs.”에는 공구에 관해 한 번 되묻는다. 후속 답 “I’ll leave them there.”까지 합쳐 이해를 확인한다.
- 두 번째 답도 모호하면 세 번째 질문 없이 지시를 안내한다. 재개 시점이 없는 공지에 내일 작업 가능 여부를 물으면 관리자 확인 필요로 표시한다.
- 서버 재시작 후 같은 링크로 발행본을 열 수 있어야 한다.

## 후속 단계 — EC2 공개 배포

로컬 리허설 후 EC2의 공개 HTTPS 주소로 같은 공지 링크를 제공한다. 팀원 휴대폰에서 카카오톡 링크를 열어보는 검증은 이 단계에 둔다. 공개 배포 시 관리자 인증 방식은 미정이며, 배포를 준비할 때 결정한다. 공개 작업자 응답 API에는 요청 횟수 제한을 적용한다.

## AI 연동과 리허설 준비

OpenAI Responses API의 gpt-5.4-mini를 사용한다. 키는 서버 환경 변수 OPENAI_API_KEY로 읽는다. 실제 AI 호출을 포함한 리허설에는 해당 API 접근과 인터넷 연결이 필요하다.
