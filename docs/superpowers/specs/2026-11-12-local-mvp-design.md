# 작업 지시 이해 지원 서비스 로컬 시연 설계

## 시연 목표

관리자가 변경 공지를 발행하고 작업자가 영어로 자신의 행동을 설명한다. 5분 발표에서는 한 노트북의 브라우저 탭 두 개를 사용한다. 첫 답에서 빠진 조건을 AI가 되묻고 두 답을 종합해 이해를 확인하는 장면까지 보여준다.

## 구성과 선택 이유

Next.js App Router 한 앱에서 화면과 서버 API를 제공하고 SQLite 파일에 발행본을 보관한다. 팀이 사용해 본 Next.js로 관리자 미리보기와 작업자 화면의 표시 컴포넌트를 공유한다. Express와 기본 HTML도 가능하지만 두 화면을 React로 구성하는 쪽을 선택했다. Vercel과 외부 DB를 연결하는 방법, EC2에서 같은 앱과 SQLite를 운영하는 방법도 검토했다. 이번에는 발표 노트북에서 실행한다. 공지 링크는 해당 노트북의 새 탭에서 연다.

## 관리자 흐름

1. 한국어 원문을 입력한다. AI가 변경 행동, 적용 시점과 조건, 상황 질문 한 개, 답에서 확인할 행동과 원문 근거를 생성한다.
2. 관리자가 한국어 요약, 질문, 판단 기준을 검수·수정하고 영어 미리보기를 생성한다. 초안을 다시 수정하면 기존 미리보기로는 발행할 수 없고 영어 미리보기를 다시 생성한다.
3. 발행 시 미리보기의 영어 공지와 질문, 검수한 기준, 원문을 함께 저장한다. 발행 과정에는 AI 호출이 없다. 공지별 링크를 복사하거나 새 탭에서 연다. 작업자에게 보내는 데이터에는 내부 판단 기준을 포함하지 않는다.

## 작업자 흐름

영어 공지와 상황 질문을 읽고 같은 입력창에 행동이나 질문을 영어로 입력한다. 서버는 발행본에 근거해 응답을 판단한다. 응답 세션은 작업자별로 구분하고 후속 답을 판단할 때 첫 답과 실제 되물은 질문도 함께 전달한다.

| 입력 상황 | 동작 |
| --- | --- |
| 기준을 충족하는 행동 | 이해 확인 후 종료 |
| 원문 지시에 어긋나는 행동 | 근거에 해당하는 행동을 영어로 안내하고 종료 |
| 행동이 모호한 첫 답 | 빠진 행동만 한 번 되묻기 |
| 되물은 뒤의 답 | 앞뒤 답을 함께 판단. 여전히 모호하면 공지에 나온 행동을 영어로 안내하고 종료 |
| 작업자가 직접 질문 | 공지로 답할 수 있으면 근거에 따라 영어로 답변. 행동 이해를 확인한 것으로 기록하지 않음 |
| 공지 근거가 부족함 | 관리자 확인 필요 표시 |

되묻기 횟수는 서버가 제한한다. AI 호출 실패는 이해 확인으로 처리하지 않으며, 입력을 보존해 재시도할 수 있게 한다. 관리자에게 실제 요청을 전달하거나 답변을 등록하는 기능, 게시판, QR은 이번 범위에서 제외한다.

## 리허설 확인 항목

- 오후 2시 옥상 작업 중단과 공구를 두고 내려오라는 공지를 사용한다. 관리자가 수정한 질문이 미리보기와 발행본에서 일치해야 한다.
- 첫 답 “I’ll go downstairs.”에는 공구에 관해 한 번 되묻는다. 후속 답 “I’ll leave them there.”까지 합쳐 이해를 확인한다.
- 두 번째 답도 모호하면 세 번째 질문 없이 지시를 안내한다. 재개 시점이 없는 공지에 내일 작업 가능 여부를 물으면 관리자 확인 필요로 표시한다.
- 서버 재시작 후 같은 링크로 발행본을 열 수 있어야 한다.

## 구현 전 확인 사항

AI 공급자와 사용할 수 있는 API 자격 증명은 미정이다. 키는 서버 환경 변수로 읽는다. 실제 AI 호출을 포함한 리허설에는 해당 API 접근과 인터넷 연결이 필요하다.
