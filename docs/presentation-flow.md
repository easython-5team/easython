# 5분 발표 시연 흐름

## 전달할 한 문장

외국인 작업자가 변경 공지를 읽었다는 사실보다 **바뀐 행동을 자기 상황에 적용할 수 있는지** 확인한다. AI는 빠진 행동을 한 번 되묻고, 잘못 이해한 행동은 공지에 근거해 바로잡는다.

## 준비

`pnpm demo`를 실행하고 관리자 화면을 연다. 데모 모드는 API 키 없이 정해진 자재 반입 예시와 영어 문장으로 동작한다. 발표 중에는 실제 AI의 자유로운 언어 이해나 번역 품질을 검증했다고 말하지 않는다. 실제 AI 시연은 별도 리허설에서 키와 인터넷 연결로 확인한다.

## 진행 순서

| 시간 | 화면과 행동 | 전달할 메시지 |
| --- | --- | --- |
| 0:00–0:40 | 기존 공지의 동쪽 출입구가 공사로 막힌 상황을 설명한다. | 공지를 읽어도 평소 방식대로 자재를 내리면 문제가 생긴다. 필요한 행동은 **서쪽 출입구 + 노란 표시 구역** 두 가지다. |
| 0:40–1:40 | 관리자 화면에서 **퀴즈 생성하고 검수하기** 후 별도 페이지의 원문 근거와 판단 기준을 보여준다. 검수 확인 뒤 **작업자 화면 미리보기**로 이동해 번역과 질문을 확인하고 발행한다. | AI 초안을 관리자가 검수하고, 승인한 번역과 질문을 저장한 뒤 공유한다. 발행 후에도 미리보기가 남는다. |
| 1:40–2:50 | 작업자 링크에서 `I'll use the west entrance.`를 제출한 다음 `In the yellow marked area in front of the first-floor materials room.`를 제출한다. | 첫 답은 출입구만 맞으므로 누락된 하역 장소를 한 번 묻는다. 두 답을 합쳐 이해를 확인한다. |
| 2:50–3:30 | 같은 링크를 새 탭에서 열고 `I'll use the east entrance.`를 제출한다. | 명백히 잘못된 행동에는 공지에 적힌 서쪽 출입구와 하역 장소를 안내한다. |
| 3:30–4:05 | 새 탭에서 `When will the group chat announce that the east entrance is available?`를 제출한다. | 공지에 없는 발표 시점을 AI가 지어내지 않고 **Manager confirmation needed**로 표시한다. 현재 MVP는 실제 요청 전달·답변 등록까지 구현하지 않았다. |
| 4:05–5:00 | 관리자와 작업자 화면을 함께 요약한다. | 핵심은 번역만 하는 것이 아니라, 변경된 행동을 확인하고 불확실한 정보는 보류하는 흐름이다. |

## 심사 기준과 증거

| 기준 | 발표에서 보여줄 근거 | 아직 검증되지 않은 부분 |
| --- | --- | --- |
| 문제 정의·사회적 의미 | 기존 기획안의 현장 의사소통 자료와 출입구 변경 사례 | 실제 현장 사용자 인터뷰와 사고 감소 효과 |
| 창의성 | 공지 번역 뒤 행동 질문, 누락 행동 되묻기, 근거 없는 질문 보류 | 다른 서비스와의 정량 비교 |
| 실효성 | 관리자가 번역을 검수하고 작업자가 오해를 수정하는 한 흐름 | 현장 사용성과 다국어 품질 |
| 기술 구현 | SQLite 발행본, 세션별 응답 기록, 재시도 처리, 데모 자동 테스트 | 공개 배포, 인증, 실제 AI 응답의 안정성 |
| 전달력 | 정상·누락·오답·근거 부족을 같은 공지로 비교 | 발표 시간 내 조작 숙련도 |

## 다음 구현 우선순위

1. 실제 AI 모드로 같은 사례를 반복 리허설하고, 번역의 시간·장소·부정·조건과 판단 결과를 사람이 검수한다.
2. **Manager confirmation needed**가 실제 관리자 확인 요청으로 이어지도록 요청 목록, 답변 등록, 작업자 재확인 흐름을 설계한다. 공개 배포 전에 관리자 인증과 작업자 요청 제한을 함께 구현한다.
3. 3~5명의 대상 사용자에게 공지 이해 전후 행동 설명을 받아, 누락 행동 발견률과 잘못된 행동 수정률을 측정한다. 이 수치는 현장 실험 전에는 제품 효과로 단정하지 않는다.
